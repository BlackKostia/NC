# План реалізації повноцінних інструментів для роботи з архівами в Duop

Цей план перетворює поточний обмежений read-only переглядач (`ARC_MAX_FILE = 4 МіБ`, `ARC_MAX_ENTRIES = 1024`, лише `F3`) на повноцінну підсистему роботи з архівами в чистому x86-64 Assembly із дотриманням усіх інваріантів Duop (`zero libc`, `.data = 0`, модулі `<= 400` рядків, рутини `<= 80` рядків, `TRY/CATCH`, `duop-tdd-first`).

---

## Етап 1. Зняття лімітів `4 МіБ` та `1024` записів (Large Archives & Streaming)

**Мета:** відкривати `.tar`, `.zip` / ZIP64 і `.tar.gz` довільного розміру без завантаження всього архіву чи розпакованого файлу в RAM.

1. **`os_mmap_file_ro` замість `fs_read_file_head(4 MiB)`:**
   - Для `.zip` і `.tar` `arc_enter_model` відкриває файл і мапить його через `os_mmap_file_ro` (автоматично реєструється в `g_pf_mmap_tab` із захистом від `SIGBUS` у [pal_fault.s](file:///home/chessplayer/DEV/NC/src/os/linux/x86_64/pal_fault.s)).
   - При закритті `ArcCtx` (`arc_free_ctx`) викликається `os_munmap` замість `mem_free`.
   - Для `.tar.gz` великого розміру: потоково розпаковувати gzip у тимчасовий файл (`tmp_open_unique` + `O_TMPFILE` або видалення при `arc_free_ctx`) і мапити цей тимчасовий `.tar` через `os_mmap_file_ro` — це дозволяє працювати з `.tar.gz` на сотні мегабайт без утримання всього tar у heap.
2. **Динамічний масив `ArcEntry`:**
   - Початкова ємність `256` записів; при заповненні подвоєння через `mem_realloc` (`256 -> 512 -> 1024 -> ...`).
   - Окремо зберігати `ArcCtx.entry_cap` (4 байти).
3. **Потоковий `inflate_stream`:**
   - Розпакування `DEFLATE` у кільцевий 32 КіБ словник із періодичним скиданням 64 КіБ чанків у вихідний `fd` (і паралельним підрахунком `crc32_update` з [hash.s](file:///home/chessplayer/DEV/NC/src/core/hash.s)).
   - Розпакування файлу на 500 МіБ із `.zip` споживатиме ~100 КіБ RAM замість 500 МіБ.

## Етап 2. Повноцінне розпакування (`F5`) та захист шляхів

**Мета:** користувач може скопіювати один файл, групу позначених файлів або цілу теку з архіву в протилежну панель через `F5`.

1. **Безпека шляхів (Anti-Zip-Slip):**
   - Функція `arc_sanitize_relpath(const char *raw, char *out, size_t cap)`:
     - Відкидає початкові `/` та будь-які сегменти `..` або `.`.
     - Забороняє NUL-байти всередині імені; перевіряє довжину `<= PATH_MAX`.
   - Усі цільові директорії та файли створюються через `openat` з `O_NOFOLLOW` (захист від symlink-перезапису).
2. **Інтеграція з `F5` та `TaskWorker`:**
   - Коли активна панель у `virtual_mode == 2` (`Archive VFS`), `F5` запускає фоновий `TaskWorker` (або прогрес-діалог `ProgressDialog`) для витягування вибраних/позначених записів або префікса директорії `sub_dir/` у `other_pane.model.path`.
   - Підтримка конфліктів (Overwrite / Skip / Rename) через існуючу логіку [task_conflict.s](file:///home/chessplayer/DEV/NC/src/fs/task_conflict.s).
   - Відновлення базових прав доступу (`fchmod` для файлів із `.tar` або POSIX external attributes у `.zip`).
3. **Перевірка цілісності (CRC32):**
   - При витягуванні запису з `.zip` звіряти обчислений `crc32_update` із полем `crc32` у заголовку; при невідповідності — видаляти пошкоджений результат і показувати локалізовану помилку в `StatusBar`.

## Етап 3. Створення архівів (`Pack` — `.tar`, `.tar.gz`, `.zip`)

**Мета:** пакування вибраних або позначених файлів і тек з панелі у новий архів.

1. **Компресор `src/fs/deflate.s`:**
   - Реалізація RFC 1951:
     - Рівень 0: `Stored` (без стиснення, миттєвий).
     - Рівень 1–6: `LZ77` (хеш-ланцюжки по 3 байти, вікно 32 КіБ) + **Fixed Huffman** (`BTYPE=01`) — компактний у коді (~250 рядків асемблера), без складної побудови динамічних дерев, забезпечує хороший коефіцієнт стиснення та високу швидкість.
2. **Записувач `src/fs/archive_pack.s`:**
   - `.tar`: запис 512-байтних USTAR-заголовків із контрольною сумою, рекурсивний обхід тек (через `openat(..., O_NOFOLLOW)`), вирівнювання блоків по 512 байт + два нульові блоки в кінці.
   - `.tar.gz`: обгортка RFC 1952 (10-байтний gzip header + потік `deflate` + 8-байтний трейлер `CRC32` + `ISIZE`).
   - `.zip` / ZIP64: запис `Local File Header` + стиснуті/stored дані + формування `Central Directory` в пам'яті/тимчасовому буфері + `EOCD` (та автоматичний перехід на ZIP64 при розмірі > 4 ГіБ або > 65535 файлів).
3. **UI та інтеграція:**
   - Додати дію пакування (наприклад, у `PopupMenu` та/або гарячу клавішу `Alt+P`) із діалогом вибору імені та формату (`.tar.gz`, `.zip`, `.tar`).
   - Синхронні EN/UA рядки в `LangStrings` ([types.inc](file:///home/chessplayer/DEV/NC/include/types.inc), [i18n.s](file:///home/chessplayer/DEV/NC/src/tui/i18n.s), [i18n_keys.s](file:///home/chessplayer/DEV/NC/src/tui/i18n_keys.s), [lang/uk.lang](file:///home/chessplayer/DEV/NC/lang/uk.lang)).

## Етап 4. Перевірка архіву (`Test Archive`) та додатковий захист

1. **Дія «Перевірити архів» (Test):**
   - Проганяє всі записи архіву через `inflate_stream` + `crc32_update` (без запису файлів на диск, у `null`-приймач) та звітує кількість перевірених файлів і помилок у `StatusBar`.
2. **Захист від Zip-Bomb:**
   - Під час `inflate_stream` та фонового розпакування перевіряти прапорець скасування (`Esc` у `ProgressDialog`) на кожному 64 КіБ чанку, щоб користувач міг миттєво перервати розпакування.

## Етап 5. План верифікації (`duop-tdd-first` & `duop-pty-verify`)

Перед кожним етапом створюються тести у `tests/test_archive_tools.py`:
- **Великі архіви:** `.tar`, `.zip`, `.tar.gz` розміром > 6 МіБ і з > 1500 файлів — відкриття, навігація, перегляд `F3` без обрізання.
- **Потоковий `inflate_stream`:** розпакування файлу > 10 МіБ із `.zip` без OOM (під `MEMCHECK=1`).
- **`F5` розпакування:** копіювання одного файлу, позначених файлів і вкладеної теки з архіву в іншу панель, перевірка SHA-256 і конфліктів.
- **Безпека:** відхилення шляхів `../../evil`, `/etc/passwd`, symlink-перезапису, виявлення пошкодженого CRC32.
- **Пакування (Round-Trip):** створення `.tar`, `.tar.gz`, `.zip` у Duop → розпакування стандартними `tar`/`unzip` Python (`tarfile`, `zipfile`) з побайтовою перевіркою вмісту.
- Фінальна перевірка через `./.agents/skills/duop-pty-verify/scripts/verify_build.sh`.
